# 搜索、阅读偏好与打印

本文档描述三组「读者侧工具」：全站搜索、阅读偏好（夜读与字号）、打印/导出 PDF，
以及与之相关的小节锚点行为与分享卡片（SEO）。

页眉右侧现在固定有两个按钮：**放大镜**（搜索）与**齿轮**（阅读设置），书架页也有。

---

## 1. 全站搜索

### 1.1 数据从哪来

索引在**构建期**由 `scripts/build-search-index.mjs` 生成到 `public/search/<bookSlug>.json`，
`prebuild` 与 `predev` 都会跑它，因此 `npm run dev` 与 `npm run build` 都不用手动生成。
产物是构建输出，已加入 `.gitignore`。

- 目录约定沿用《项目说明.md》第 4 节：**每本书在 `data/` 下占一个平级文件夹，文件夹名即 slug**。
  若将来某本书的 `dataDir` 不再等于 `data/<slug>`，脚本要同步改。
- 每篇文章的正文被洗成纯文本，并按 `###` 切成小节，因此搜索结果能直接落到小节锚点。
- `索引 Index.md` **不作为文章**参与搜索，改为解析成词条（主名 / 别名 / 释义）；
  否则每条正文命中都会撞上索引那 550 条重复文字。
- 字段名压到一个字母（`s`/`t`/`e`/`c`/`h`/`i`/`n`/`a`/`d`），因为整本书的正文都在里面，
  key 会重复上万次。

**刻意不做分词与倒排**：中文没有词边界，真要分词就得引依赖；而全书纯文本也就二十六万字符，
浏览器里一次 `indexOf` 是微秒级的事。匹配就是 `includes`。

### 1.2 与 headings.ts 的重复

小节锚点 id 的生成规则（`slugify` + 重名编号）在脚本里复制了一份——脚本是 `.mjs`，
没法 `import` `.ts`。两边都写了注释互相指认，**改一处必须同步另一处**，否则搜索结果里的
小节锚点会跳空。同样的重复还有 `stripMarkdown`（对应 `src/lib/plain-text.ts`），
那一处不同步只会让摘要略有出入，不会出错。

### 1.3 交互

- 唤起：页眉放大镜、`Ctrl/Cmd + K`、`/`（正在别处输入时不抢）。
- 范围：默认搜当前书；勾选「全站搜索」扩到全部书籍。书架页没有「当前书」，默认即全站。
- 排序意图是「先给你要找的那篇/那个词，再给正文里提到过的」：
  文章标题命中 → 词条名命中 → 小节标题命中 → 正文命中（同级按出现次数）。
- ↑↓ 选择、回车打开、Esc 关闭；单篇文章最多贡献 3 条结果，总数上限 40。
- 词条命中跳到该书**索引速查页并带 `?q=<主名>`**，速查页据此预填搜索框
  （已经在索引页时再搜另一个词，组件不会重新挂载，靠渲染期对比 `?q=` 变化丢掉上一次输入）。
- 索引 850KB，**只在第一次打开搜索时才拉**，缓存在模块作用域里，同一次会话内换页不会重下。

### 1.4 一个必须记住的坑

搜索浮层**必须 portal 到 `document.body`**。组件长在页眉里，而页眉带 `backdrop-blur`；
带 `backdrop-filter` 的祖先会成为 `position: fixed` 后代的**包含块**，不 portal 的话
整个浮层会被裁进页眉那一条里。索引释义卡片（`IndexTermPopover`）出于同样的原因也用 portal。

### 1.5 实现位置

| 用途 | 路径 |
|---|---|
| 构建期索引生成 | `scripts/build-search-index.mjs` |
| 数据形状与匹配/排序 | `src/lib/search-index.ts` |
| 搜索浮层与快捷键 | `src/components/SiteSearch.tsx` |

## 2. 阅读偏好：夜读模式与正文字号

### 2.1 主题

- 三档：**日间 / 夜读 / 跟随系统**，写在 `<html>` 的 `data-theme` 上（跟随系统时不写属性）。
- `globals.css` 里有**两份**夜读调色板，值必须保持一致：
  - `@media screen and (prefers-color-scheme: dark) { html:not([data-theme="light"]) { … } }`
    服务「跟随系统」，`:not` 让显式选了日间的人不被系统设置反悔；
  - `@media screen { html[data-theme="night"] { … } }` 服务显式选择，
    特异度与上面相同，靠书写顺序在后取胜。
- 两块都限定在 `@media screen` 内，这样**打印时夜读自动不生效**，不必在打印样式里重述浅色变量。
- 注意 `--gold-dark` 全站当作悬停强调色用，暗底下它必须比正文**更亮**而不是更暗。
- 背景世界地图的浓度随主题变化，因此从 Tailwind 的 `opacity-*` 挪到了
  `.world-map-backdrop`（书内页）与 `.world-map-shelf`（书架页）两个类。

### 2.2 字号

- 四档，写在 `<html>` 的 `data-reading-size` 上，落到 `--reading-scale`。
- `.article-markdown` 的基准字号是 `calc(1rem * var(--reading-scale))`，
  **各级标题一律用 `em`** 跟着缩放；折叠块标题不在 `.article-markdown` 内，单独乘同一变量。
  新增正文相关的字号规则时请沿用这个约定，否则会出现「正文变大、标题不动」。

### 2.3 防闪白

站点是静态导出，服务端无从得知读者偏好。若等 React 挂载后才改，每次刷新都会闪一帧日间配色，
因此偏好由 `layout.tsx` 注入的一段**首屏内联脚本**在绘制前写到 `<html>` 属性上。
键名与脚本本身都在 `src/lib/reading-prefs.ts` 单点定义。

## 3. 打印 / 导出 PDF

入口：阅读设置面板里的「打印本篇 / 存为 PDF」，与 `Ctrl+P` 同一条路径。

- `globals.css` 末尾的 `@media print`：去掉站点页眉页脚、左右两栏导航、上一篇下一篇、
  搜索浮层，以及索引名词的底色与虚线（那是「可以点」的提示，印出来没有意义）。
- 页眉选择器写作 `body > header`——**文章标题块本身也是一个 `<header>`**，
  写成 `header` 会把文章标题一起藏掉。
- 背景世界地图连同它 `position: fixed` 的容器一起用 `:has()` 去掉，
  否则 fixed 元素会被复制到每一页甚至撑出空白页。
- **折叠块**收起时内容根本不在 DOM 里，纯 CSS 救不回来：
  `MarkdownWithFoldBlocks` 监听 `beforeprint`，用 `flushSync` 同步展开全部，`afterprint` 恢复。
  展开前的状态存在 **ref** 而不是闭包变量里——钩子若依赖 `expanded`，
  它自己触发的展开会立刻重建监听器，`afterprint` 拿到的就是一副空快照，恢复不回去。
  同理该 effect 的依赖里只能有 `foldCount`。

## 4. 小节锚点（`###`）

- id 仍由 `ArticleHeadingIdInjector` 在客户端挂载后注入（原因见 `02_文章页与内容渲染.md` 第 6 节）。
- **冷启动跳转**：浏览器解析 `#小节` 的那一刻 id 还不存在，因此注入完成后要补一次滚动。
  用 `setTimeout` 而**不是** `requestAnimationFrame`——后台标签页里 rAF 根本不跑，
  而「在新标签页打开别人发来的锚点链接」恰恰是这个功能最主要的使用场景。
  滚两次（立即 + 60ms），后一次盖掉 App Router 随后可能做的回到顶部。
- 各级标题带 `scroll-margin-top: calc(4rem + 3.5rem)`，浏览器原生跳转与 Next 的 hash 滚动
  都吃这个值，不必各自算偏移。JS 侧的偏移常量是 `headings.ts` 的 `HEADING_SCROLL_OFFSET_PX`，
  两者数值相同。
- 每个 `h3` 后面追加一个复制链接按钮，平时隐形、悬停标题才浮现。
  按钮本身也是 childList 变更，注入时**先断开 MutationObserver 再改**，否则回调会自我触发成死循环。

## 5. 分享卡片与 SEO

- 根 `layout.tsx` 设 `metadataBase`（`https://finzhang.space/Nurania/`）与站点级
  `openGraph` / `twitter`，各页只给相对路径即可补全成绝对地址——
  分享卡片里的相对路径在别的 App 里打不开。
- 文章描述取正文纯文本开头 120 字；索引页正文已被清空成速查视图，退回书籍简介。
- 配图优先用文章题图，没有题图退回该书封面。
- `src/app/sitemap.ts` 与 `src/app/robots.ts` 在静态导出下会写成
  `out/sitemap.xml` 与 `out/robots.txt`，地址一律是含 basePath 的绝对形式。
- **已知限制**：文章页因为用了 `useSearchParams`（移动端侧栏开合以 URL 为单一数据源），
  在静态导出下整个文章子树会 `BAILOUT_TO_CLIENT_SIDE_RENDERING`，
  正文不在静态 HTML 里、只在 RSC 载荷里。`<head>` 中的 title/description/og 不受影响，
  会执行 JS 的爬虫（如 Google）也能拿到正文，但不执行 JS 的抓取方看不到。
  真要改，得把侧栏开合从 URL 挪回组件 state。

## 6. 自定义 404

`src/app/not-found.tsx`，静态导出会写成 `out/404.html`。主机需配置成用它兜底；
本地 `npm run preview` 用的 `serve` 只认服务根目录下的 `404.html`，看不到效果，
可直接访问 `/Nurania/404.html` 验证。

页眉在这类**非书籍路径**上的判断以 `book` 为准而不是 `bookSlug`：
404 这类路径也有第一段，但它并不是一本书。
