## 开发者指令

### 1. 全局样式

- 在 `src/app/globals.css` 维护「奇幻史诗」主题色板与站点统一视觉基调。

### 2. 组件化与响应式

- 导航栏、页脚、内容区均为独立组件，避免把页面逻辑堆到单一文件。
- 所有页面需同时适配移动端窄屏与电脑宽屏（包括目录/文章区域的结构开关）。

### 3. 数据驱动（新增书籍/内容扩展）

- 文章与目录结构由 `data/{书}/` 下的 Markdown 与 `_order.json` 驱动。
- 扩展新增书籍时，主要通过：
  - 在 `src/lib/books.ts` 的 `BOOKS` 数组增加一项；
  - 在 `data/` 与 `public/` 下按同名建立对应目录结构；
  - 无需在页面组件里写死具体条目。

### 4. 内容更新后的例行检查

- 改过正文或 `索引 Index.md` 之后，部署前跑一次 `npm run audit:index`：
  索引名词高亮是逐字符最长优先匹配，二字词条会切进别的词中间（「大海里」里的「海里」），
  这类误配不报错、页面照常渲染，只有把命中连同上下文摊开看才发现得了。
- 发现误配就在索引文件的该条目行补忌配串 `〔忌配：…〕`，不改代码。
  完整工作流见 `siteDocu/02_文章页与内容渲染.md` 第 7 节「误匹配的排查工作流」。
