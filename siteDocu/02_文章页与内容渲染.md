# 文章页与内容渲染

本文档承接 `项目说明.md` 中“文章页与内容渲染”相关部分（5.5-6）。

目标：描述文章页面在站点内的可见行为、以及内容层面的写法/语法约定；避免重复 `siteDocu/内容与 Markdown 合约.md` 中的那些“写作规则总览”（两者会做边界划分）。

## 1. 文章页（`/[bookSlug]/article/[...slug]`）布局与滚动行为

- 宽屏：
  - 三栏：左侧书目录导航（固定高度、可独立滚动）+ 中间文章区域 + 右侧文章内 `###` 导航（仅在存在 `###` 时出现）。
  - 页面滚动交互：
    - 当滚动发生在“文章区域”时：允许整页滚动，同时页眉吸顶效果生效。
    - 当滚动发生在“左侧导航”时：仅导航栏滚动，整页滚动不会被触发。
  - 左侧导航滚动条为透明底、淡棕色细条，悬停加深；仅在切换文章（`currentSlug` 变化）时自动把当前项滚入可视区。
- 窄屏：
  - 通过页眉里的「本书目录」打开侧栏目录；侧栏逻辑与原先一致。

## 2. 题图（Title Image）

- 用途：在文章正文标题下方的任意位置插入一行题图注释代码。
- 语法：`<!-- 题图 路径 -->`
- 路径：相对全局 `public` 目录。
  - 例如：`<!-- 题图 compendium/诸国列志/索拉瑞斯.webp -->`
- 渲染行为：
  - 宽屏：题图在文章右上角浮动（float-right），上边缘略低于文章标题。
  - 窄屏：题图占一整行，位于正文上方。
- 解析行为：题图注释行在渲染时会从正文中移除，不会显示为文本。

## 3. 插图（Illustration）

- 用途：在正文任意位置插入一张随正文流动、文字环绕的插图（题图的通用化版本，一篇可插入任意多张）。
- 语法：`<!-- 插图 路径 [左|右|整行] [宽度] [比例=宽/高] [可放大] [注=图注文字] [描述=替代文本] -->`
  - `路径`：相对全局 `public` 目录，如 `compendium/诸国列志/索拉瑞斯.webp`。
  - `左|右|整行`（可选）：版式。`左`/`右`为浮动、正文环绕，缺省为右；`整行`不浮动、独占一整行并居中（也可写 `独占`/`整幅`）。
  - `宽度`（可选）：宽屏下的图片宽度，可写 `240`、`240px`、`40%`、`20rem`；浮动插图缺省 340px 且不超过正文栏宽的 60%，整行插图缺省占满正文栏宽。
  - `比例=宽/高`（可选）：图片加载完成前的占位宽高比（如 `比例=3/2`），加载后一律改用图片真实比例。
  - `可放大`（可选）：点击图片打开灯箱，可滚轮缩放、拖动平移、双指缩放；点击遮罩或右上角关闭（也可写 `放大`/`可缩放`/`zoom`）。
  - `注=图注文字`（可选）：图注，渲染在图片下方居中小字。
  - `描述=替代文本`（可选）：图片 `alt`；不写时依次取图注、文件名。
  - 参数顺序不限；`注=` 与 `描述=` 各自取值到下一个文字参数为止，因此可同时出现。
  - 例：`<!-- 插图 compendium/诸国列志/索拉瑞斯.webp 左 240 注=索尔因的城墙 -->`
  - 例（整行大图并可放大）：`<!-- 插图 compendium/world_map_labelled.webp 整行 可放大 比例=16/9 描述=诺拉尼亚大陆地图（标注版） -->`
- 渲染行为：
  - 宽屏：浮动插图排在正文一侧、正文环绕，图片上沿与插图代码所在行的正文对齐（即紧随其后的那行文字）；整行插图独占一行，描边与投影更重，接近独立图版。
  - 窄屏（< 768px）：插图一律不浮动，占整行，正文在其上下。
  - 图片按占位比例先占位，加载完成后改用真实宽高比，避免留边。
  - 可放大插图：图框为按钮（放大光标、可键盘聚焦），灯箱内按图片真实比例展示，初始放大 1.2 倍，缩放范围 0.3–4 倍。
- 书写建议：插图代码单独占一行（前后留空行），插入点即为图片上沿位置。
- 解析行为：插图代码在渲染时从正文中移除，不会显示为文本；参数写错时该参数被忽略，不影响图片显示。
- 实现位置：`src/lib/illustrations.ts` 负责解析与切分，`ArticleMarkdown` 在统一渲染入口按代码位置把正文切开并插入浮动图片，因此普通正文、题图文章、折叠块内部都同样支持插图。
- 与题图的关系：题图是固定悬挂在文章右上角的单张图（见第 2 节）；需要正文中段配图时用插图。
- 大陆地图：`大陆总览/地理概述` 顶部的可放大世界地图即由本节的插图代码实现（此前是写死在文章页组件里的专用组件，现已统一到插图）。

## 4. 折叠块（Fold Blocks）

- 用途：在任意 `.md` 中把一段内容渲染为可折叠块。
- 语法：
  - 起始：`::: fold 标题文字`（行首可带空格；也允许 `:::fold 标题`）
  - 结束：单独一行 `:::`（半角）或 `::: endfold`（行首须为 `:::`）
- 标题渲染：
  - 标题支持 Markdown（例如在标题行写 `### 神启学派-祷言`）。
  - 当标题行无格式标记（无 `#`、`**`、`*` 等）时，使用正文格式（字体与字重与正文一致）。
  - 标题左对齐，与正文一致。
- 内容处理要点：
  - 若块内首行为 `### 纯文本标题`，且与折叠标题的纯文本一致，则渲染时会去掉该行以避免重复。
  - 开头多余空行会被压缩为至多一个段落间距。
  - 展开后，折叠内容区顶部仅保留一行正文高度（约 `1.75em`），避免第一行距离标题过远。
- 吸顶与交互：
  - 折叠块标题吸顶状态下点击收起，会保持标题停留在吸顶位置；收起后再随页面正常滚动。

## 5. 题图与折叠块共存与重叠避让

- 同一篇文章既有题图注释又有折叠块：两者都会显示。
- 重叠规则：如果题图“覆盖”到第一个折叠块起始行（即第一个 `::: fold` 所在行不晚于题图插入行），则会给第一个折叠块额外上边距（宽屏约 600px），把折叠块整体下移，避免与题图重叠。

## 6. 文章内导航（h3：`###` 提取与跳转）

- 展示条件：仅宽屏显示；当文章正文包含三级标题（`###`）时显示。
- 导航内容：按从上到下顺序列出所有 `###` 标题（不含总标题）；每条带书签图标与上下分割线。
- 跳转行为：
  - 点击条目会平滑滚动到对应小节。
  - 滚动位置会预留页眉高度及约两行正文间距，避免被吸顶页眉遮挡。
  - 链接使用当前页 pathname + hash，兼容站点 `basePath`。
- 题图文章的兼容性：
  - 题图页会渲染多套 DOM（如宽屏/窄屏视口差异），id 会赋给“最后一套”（当前可见视口）。
  - 点击导航时优先滚动到可见元素，确保宽屏带题图时跳转正确。
- 实现要点（用于理解行为来源）：
  - `extractH3Headings`：从 Markdown 中按序提取所有 `###` 并生成唯一 id。
  - `ArticleHeadingIdInjector`：客户端挂载后为文章容器内的 h3 依次注入 id；并在折叠块展开后补注（通过观察折叠展开导致的 DOM 变化）。

## 7. 索引名词高亮与悬浮释义

- 数据来源：每本书 data 目录**根层**的 `索引 Index.md`。
  - 文件名是全套功能里**唯一写死的东西**，常量在 `src/lib/index-terms.server.ts` 的 `INDEX_BASENAME`，
    被三处使用：查找索引文件、在 `content.ts` 里识别「这一页是索引页」、以及把索引排除出「最近更新」。
  - **没有这个文件的书自动不启用本功能**，将来哪本书要，放一个同名文件即可。
  - 改名或挪进子目录 ＝ 整套功能静默关闭：全站不再高亮，该文件退回成普通 Markdown 文章按原文渲染，
    并重新出现在「最近更新」里。不报错也不崩，但同样没有任何提示。真要改名，改上述那一个常量即可。
- 条目格式（一行一条，索引文件内）：

  ```
  **主名（别名1/别名2）**　释义正文。（出处1.md；出处2.md）
  ```

  - 主名与 `**` 之间不留空格；`**` 之后用**全角空格**分隔释义。
  - 别名与主名共用同一条目：主名高亮过之后，后文再出现别名也不再高亮。
  - 释义末尾的出处括号（分号分隔、各段以 `.md` 结尾）在展示时**自动删去**，悬浮窗只显示释义正文。
  - 释义里可写**忌配标注**，声明「这个上下文里的同形字不是我」：

    ```
    **海里**　长度单位……〔忌配：大海里、海里面〕
    ```

    - 中文没有词边界，二字名称必然会切进别的词中间（「大海里」里的「海里」、「根深叶茂」里的「叶茂」）。
      忌配串就是那些**包含本条名称、但整体另有其义**的更长上下文；正文命中位置落在忌配串之内即不作数。
    - 标注写在释义任意位置均可（出处括号前后都行），分隔符 `、，,/／;；` 通用；解析后从释义中删去，
      悬浮窗与搜索结果都看不到它。
    - 挡下的只是**这一个位置**，不影响该名称在别处的匹配，也不影响更短的名称在同一位置匹配。
    - 忌配串若不含本条任何可匹配名称（写错字、或写给了单字名）则永远不生效；
      这种情况不报错，由 `findUselessGuards` 交给调用方列出提醒。
- 文件结构的自由度（除条目格式外，几乎都可以随便改）：
  - **可自由改动**：frontmatter 的 `title` / `titleEn`、正文的 `# 大标题`、开头的说明段落、结尾附注、
    `---` 分隔线、`##` 大部与 `###` 分类的名称与数量、条目顺序。这些全部是动态解析的，没有一处写死。
  - 条目 id（`e0`、`e1`…）按文件顺序在**每次构建时重新生成**，不在任何地方持久化，
    因此增删条目与重排顺序都是自由的，不会留下失效引用。
  - 开头说明 ＝「首个 `##` 之前、且不是 `#` 标题行与 `---` 的那些行」，删光即整块不渲染；
    结尾附注 ＝「最后一条词条之后的非空、非 `---` 行」，同理。
  - `##` 大部行是可选的：没有时会自动合成一个无名大部，页面上也不会多出一个空标题。
  - **唯一的约定：词条要落在某个 `###` 之下。** 落在外面的（排在首个 `###` 之前，或夹在 `##`
    与其首个 `###` 之间）会被收进一个挂在页面末尾的「未分类」分类——不会出现「解析得到了、
    速查页上却看不见」的情况。正常的索引文件里不会出现这个分类；一旦看到它，就说明有词条
    漏在了章节结构之外。兜底分类名见 `index-terms.ts` 的 `UNCATEGORIZED_TITLE`。
- 高亮规则：
  - 每个条目在**一篇文章内只高亮首次出现**；标题行、代码块、既有链接、题图/插图注释内不高亮，也不占用「第一次」。
  - 折叠块（`::: fold`）内**单独计数**：每个块像一篇小文章各自从零开始，避免首次出现被藏在默认收起的块里。
  - 索引页自身不高亮，保持纯文本。
  - **长度为 1 的条目不参与自动匹配**（如「虚」「旬」），否则会在「虚构」「上旬」这类词里大量误命中。
  - 名称互为子串时按**最长优先**匹配（如「秘术式」不会被拆成「秘术」）。
  - 二字名称切进别的词中间时，靠条目自带的**忌配串**挡下（写法见上）：不引分词库——
    实测 `Intl.Segmenter('zh')` 把「大海里」切成「大 / 海里」，正好切反；
    jieba 一类还要为自造词维护用户词典，收益不抵成本。
- 交互：
  - 桌面悬停、触屏点按弹出释义卡片；卡片内的索引名词同样可展开，形成可逐层堆叠的窗口栈（上限见下）。
  - 卡片内的释义**各自独立**计数「第一次」，因此同一条目无论从哪条路径打开，看到的高亮都一致。
  - **祖先链抑制**：索引条目之间存在循环引用（四大元素→神启魔法→神启学派→四大元素…），
    若不加处理，读者可以在环里无限点下去。因此已在当前这条弹窗链上游展开着的条目，
    在下游卡片里退回普通文字（不高亮、不可点）——等于把「已高亮」的作用域从「每个窗口」收窄到「每条链」。
  - **堆叠上限 4 层**（含由正文打开的第一张）：达到上限后，最深那张卡里的名词同样退回普通文字。
    上限不采用「挤掉栈底/替换栈顶」的滑动窗口，因为子卡片的锚点元素就长在父卡片里，移除父卡会让子卡失去定位基准。
  - 关闭方式只有三种：点击卡片与名词之外的位置（关全部）、点卡片右上角的 ×（关该层及更深层）、`Esc`（关最上层）。
    **指针移开不会自动关闭**——释义需要时间读完，鼠标稍一挪动就消失是不能接受的。
  - 唯一的例外是滚动：**锚点名词被滚出可视区域（以吸顶页眉下沿为上界）时自动关闭整条链**。
    卡片是 `position: fixed` 且会被夹在视口内，不关的话它会脱离原文、钉在视口边缘变成一张无处可依的幽灵卡片。
    只有第 0 层的锚点长在正文里会随页面滚动，更深的锚点长在 fixed 的父卡片内，因此实际触发的总是第 0 层，而关第 0 层本就连带关掉整条链。
  - 悬停 250ms 才弹出：卡片既然不随指针移开而关，弹得太轻率就会在扫视正文时一路留下卡片。
  - 因此正文里悬停另一个名词是「替换」而非「叠加」：第 0 层重新打开会截断整条链，屏幕上不会堆出无关的卡片。
  - 切换文章时弹窗栈会清空（App Router 会复用组件实例，否则旧卡片会带着已卸载的锚点留在屏幕上）。
- 索引页本身（速查视图）：
  - 索引不适合当散文读——五百余条词条分二十余类，读者要的是「按名字查」与「按类浏览」。
    因此索引页不走普通 Markdown 渲染，而是由 `IndexQuickLookup` 渲染成速查视图。
  - 顶部吸顶工具条：搜索框（匹配主名、别名与释义全文）＋「简目 / 详解」切换。
  - **简目**（默认）只铺开词条名，点任一条弹出与正文相同的释义卡片；**详解**逐条列出释义，
    释义里的其他名词依旧可点。简目下页面高度约为详解的五分之一。
  - 索引页**不显示右侧文章内导航**：分类的定位职责已由速查页自带的搜索框与分类计数承担。
    因此该页的 `content` 直接置空，不必把索引原文（近 90KB）塞进页面数据。
  - 分类标题一律渲染，搜索命中为零时用 CSS 隐藏而非卸载：搜索每敲一个字都会重算命中，
    卸载再挂载二十余个小节纯属浪费。
  - 索引会随正文每次增补而改动，但它不是「新内容」，因此 `getRecentArticles` 把它排除在目录页的
    「最近更新」之外。
- 实现要点：
  - `src/lib/index-terms.ts`：解析索引（`parseIndexDocument`，含「未分类」兜底）、构建匹配器、把首次出现改写成 `[原文](#idx-e123)` 形式的链接，并求本页所需词条的传递闭包。匹配与改写在**服务端（构建期）**完成，不改变正文行数，因此题图插入行号、折叠块行号与 `###` 锚点均不受影响。
  - `src/lib/article-md-components.tsx`：把 `#idx-` 开头的链接换成名词标记组件。
  - `IndexTermProvider` / `IndexTermMark` / `IndexTermPopover`：状态中枢、名词标记与释义卡片。
  - `IndexQuickLookup` / `TermRichText`：索引页速查视图，以及释义的轻量渲染器
    （释义是纯文本，唯一标记就是词条链接，详解模式一次要渲染五百余条，用 ReactMarkdown 会在每次敲搜索词时重解析）。
- 误匹配的排查（写完新正文后做一次）：

  ```bash
  npm run audit:index                  # 仅列二字名称的命中，误配几乎都出在这里
  npm run audit:index -- --all         # 列出全部命中
  npm run audit:index -- --term 海里   # 只看某个名称
  ```

  - `scripts/audit-index-terms.mjs` 把全站每一处实际标记连同上下文摊开，人工扫一眼即可发现
    「大海里」这类切错的命中，再回索引文件补忌配串。顺带列出失效的忌配串。
  - 它**直接 import `src/lib/content.ts`** 走真实渲染管线（靠 Node 的类型擦除跑 `.ts`，需 Node ≥ 22.18），
    而不像 `build-search-index.mjs` 那样重写一份逻辑——报告一旦与正文实际标记有出入就会骗人。
  - 因为吃 Node 版本，它是**手动运行的维护工具，不挂进 `prebuild`**，免得构建被环境卡住。

## 8. Markdown 与内容合约（只保留文章页所需部分）

- 文章 Markdown：
  - frontmatter 支持 `title`、`titleEn`。
- 目录顺序：
